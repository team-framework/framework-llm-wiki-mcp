# 작업 및 검증 기록

## 2026-09-29 · 설계와 초기 구현

- 세 가지 토큰 절감 방식을 비교하고 사용자의 선호에 따라 Qdrant 하이브리드 검색을 선택했다. Markdown 정본, 부분 읽기·수정, GitHub Draft PR을 유지한다.
- 웹은 팀 GitHub 인증, Discord 승인은 논의 참여자 누구나, 대화 참여는 멘션·Agent 답글 회신으로 확정했다.
- 서버 정본 157개 문서의 기존 MCP payload를 `o200k_base`로 계산했다. 본문 중복 제거와 compact JSON을 적용한 비교값은 1,015,366 → 566,422 tokens, 44.21% 감소다. 문서마다 한 번씩 읽은 응답 크기 합이며 실제 모델 사용량은 아니다.
- 로컬 TypeScript 검사와 테스트 21개가 통과했다. 검증 범위는 인증, 챗봇 입력·동시 요청·오류 보호, 원문 단락 분할·이어 읽기·경로 보호, 검색·벡터 hash 검증, 부분 수정 충돌 처리다.
- 별도 loopback 추론 서비스에서 Hermes OAuth `gpt-6-luna / low`의 실제 응답을 확인했다. 검증 질문에 `Markdown`으로 답했고 provider usage는 입력 63, 출력 5 tokens였다. 문서 검색 전체 흐름 검증은 아직 아니다.
- 루트 Node 의존성 감사에서 발견한 5건을 호환 범위 업데이트로 처리했고 재검사 결과는 0건이다.
- 기존 운영 서비스와 원래 checkout의 미커밋 변경을 보존하며 별도 작업 폴더·서버 preview에서 구현한다.

다음 검증: 실제 로컬 임베딩·Qdrant 한국어 검색, Fumadocs 빌드·화면·인증, 전체 문서 챗봇, Discord 범위·승인·PR 연결. 진행 상태를 배포 완료로 해석하지 않는다.

## 2026-09-29 · Hermes 문서 챗봇 추론 경로

- `WikiChat`이 제한된 질문·대화 기록·원문 근거를 서버의 OAuth 추론 브리지에 전달하고 출처 목록을 반환한다.
- 기본 모델은 `gpt-6-luna`, 기본 추론 강도는 `low`다. 잘못된 role·초과 입력·동시 요청을 차단하고 provider 오류 원문을 사용자에게 보내지 않는다.
- 브리지는 loopback에서만 수신하며 공유 key를 검사한다. 별도 shell/파일/MCP 도구와 지속 대화 상태를 제공하지 않는다.
- 챗봇 단위 테스트 5개 및 Python 문법 검사 통과. 서버의 실제 OAuth 응답 확인 완료. HTTP 경로·웹 통합 검증은 후속 단계다.

## 2026-09-29 · 단락 검색과 부분 수정

- MCP에 `get_context`, `get_note_outline`, `read_sections`를 추가하고 전체 읽기에서 중복 본문을 제거했다. 키워드와 hash가 일치하는 벡터 후보를 RRF로 합친다.
- 로컬 `wiki:patch`는 dry-run을 기본으로 하며 문서·섹션 hash와 적용 직전 상태를 검사한다. 기존 checkout 밖 경로와 symlink 이탈을 차단한다.
- TypeScript 검사·테스트 21개·diff 공백 검사 통과.
- 같은 157문서 snapshot, `o200k_base`, lexical 검색 8질의에서 도구 payload 210,278 → 47,985 tokens, 77.18% 감소(질의별 중앙 75.67%).
- 대형 문서 20개의 섹션 수정 요청 비교는 406,787 → 93,600 tokens, 76.99% 감소(중앙 74.99%). 실제 LLM 작업 실행 비용 비교가 아니다.
- 신규 문서 20건은 같은 본문을 전달하면 54,898 → 57,175 tokens로 프로토콜 오버헤드가 4.15% 추가됐다. 새 지식 작성 자체가 줄었다고 해석하지 않는다.
- 벡터 검색 품질과 답변 정확도는 별도 평가 전이다. 크기 측정만으로 근거 recall 유지를 주장하지 않는다.

## 2026-09-29 · 실제 벡터 색인

- Qdrant와 CPU 다국어 임베딩을 별도 서비스로 실행했다. 서버 preview에서 정본 157문서, 1,481섹션, 1,785벡터 chunk의 색인이 `ready`에 도달했다.
- 임베딩 계약·원문 hash·manifest를 검사하고 완성된 generation만 alias로 공개한다. 캐시 재사용, 중복 chunk 제거, metadata filter, 실패 시 이전 alias 보존을 테스트했다.
- 한국어·emoji·긴 코드·공백·긴 문자열의 분할 5사례에서 원문 범위 보존과 512-token 입력 제한을 확인했다.
- 독립된 10질의 첫 평가에서 기존 검색·전체 읽기 대비 hybrid 응답 토큰은 74.23% 감소했다. 필수 근거 회수는 6/11에서 7/11이었다. 작은 표본이며 문서별 편중과 현행 수치 누락을 확인해 순위 개선 후 재평가한다.
- 운영 포트, key 구분, 색인 갱신·복구, 읽기 예산을 `docs/operations.md`에 기록했다.
