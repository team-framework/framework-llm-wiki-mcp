# 2026-09-29 위키 토큰 비교 자료

위키 snapshot 157문서를 보존하고, 전체 읽기·구간 읽기·부분 수정·신규 작성을 나누어 측정했다. tokenizer는 `o200k_base`다. 평가 입력과 비공개 응답은 운영 서버의 접근 제한된 평가 폴더에 보존한다. 공개 저장소에는 원문을 제외한 집계와 재현 코드를 둔다.

## 결과와 해석

고정 정답 평가에서 기존 검색과 상위 3문서 전체 읽기는 278,972토큰을 반환했다. 개선한 구간 hybrid 검색은 54,502토큰으로 80.46% 줄었고, 필요한 근거는 6/11에서 9/11로 늘었다. 질문 전체에 필요한 근거를 찾은 경우는 5/10에서 8/10으로 늘었다.

구간 lexical 검색만 사용해도 54,448토큰이었다. 따라서 80.46% 전체를 Vector DB 효과로 설명하지 않는다. 반환 예산·절 단위 읽기·중복 제거·순위 개선이 전달량을 줄였고, 이 평가에서 vector 결합은 54토큰을 추가로 사용하면서 근거 1개를 더 찾았다. 찾지 못한 근거 2개는 후속 검색·원문 확장이 필요하다.

별도 8질의 크기 비교에서는 읽기 210,278→40,293토큰(80.84%), 20개 합성 부분 수정에서는 406,787→93,600토큰(76.99%)이었다. 신규 문서 본문을 동일하게 전달하면 54,898→57,175토큰으로 4.15% 늘었다. 새 지식을 쓰는 양 자체는 줄지 않으며, 생성 전 문맥 조회와 지침을 줄이는 것이 목적이다.

크기 비교의 8개 질의에는 별도 정답 판정이 없다. 수정 시나리오는 실제 원문을 변경하지 않은 합성 요청이고, 모델 입력·추론·출력 비용을 청구서에서 비교한 실험이 아니다. 운영 실사용·재방문·만족도는 배포 이후 별도 수집한다.

## 다시 실행하기

상위 `measurement-plan.md`의 고정 평가 CLI를 따른다. `scripts/evaluate-retrieval.ts`는 원문과 manifest가 다른 vector 색인을 거부하고 검증한 immutable collection을 조회한다. `scripts/benchmark-tokens.ts`는 읽기·수정·작성의 payload 크기를 계산한다. 전후를 비교할 때 질의, 정답, corpus, tokenizer, 반환 예산, 모델, 코드 버전을 고정한다.

실제 사용 자료는 로그인한 웹의 `/docs/insights`에서 7·30·90일 JSON을 내려받는다. 보고 생성 시각·관측 완료 여부·분모·release를 함께 남긴다. 아직 관측하지 않은 과거 사용량은 이 replay 결과로 채우지 않는다.
